DESIGN SYSTEM SOURCE: Every build has a `governance/DESIGN_SYSTEM.md` written by FORGE's UX Intelligence layer (`src/skills/ux-intelligence.ts`) before Phase 3 ever runs. Phase 0 reads whatever `PRD.md`/`BLUEPRINT.md` text already exists on disk, classifies the product's industry vertical (fintech, healthcare, legal, creative, enterprise, commerce, education, or the `saas` default) via `detectIndustryVertical`, and selects a curated starter design system via `selectDesignSystem` — a full color palette, a heading/body/mono type pair, a layout density, and a motion profile, each tuned to that vertical's real-world conventions. Treat this file as the authoritative starting palette/type/density/motion for the build unless a later, fuller design-system generation (Phase 1B's UI/UX Pro Max pass) has already overwritten it with a more complete, PRD-informed system — check the file's own header for which stage produced it.

VERTICAL-APPROPRIATE DEFAULTS, NOT ARBITRARY CHOICES: A fintech build gets a compact, subtle-motion, trust-signaling blue palette because financial UIs are read as precise, not decorated. A creative-agency build gets spacious, expressive-motion, saturated color because the product IS the portfolio piece. A legal build gets a serif heading paired with a plain sans body — an editorial pairing, not a "product" one — and near-absent motion. Never override the selected palette/type/density/motion with a generic default "because it looks fine" — the vertical-specific choice is deliberate and documented in the file's own Rationale section.

COLOR USAGE: Use the eight semantic roles exactly as named — `primary`/`secondary`/`accent` for brand and emphasis, `background`/`foreground` for the base surface and text, `error`/`success`/`warning` ONLY for their semantic state (never repurpose `error` red as a decorative accent). Every color ships as both a CSS custom property (`--color-primary`, etc., under `:root`) and a Tailwind `theme.extend.colors` entry — wire Tailwind classes (`bg-primary`, `text-foreground`, `border-error`) to the config fragment in `DESIGN_SYSTEM.md`, never hardcode a hex value directly in a component.

TYPOGRAPHY: Three roles only — `heading`, `body`, `mono`. Load exactly the fonts named in the `Typography` table (via `next/font` for a Next.js project, or the project's existing font-loading convention) and map them to Tailwind `fontFamily.heading`/`fontFamily.body`/`fontFamily.mono`. Do not introduce a fourth font family or substitute a different weight/family "for variety" — the pairing was chosen deliberately for the detected vertical.

LAYOUT DENSITY: `compact` (fintech, enterprise) means tables and dense lists over cards, minimal whitespace between related items, a tight 4/8/12/16px spacing scale. `spacious` (creative, education) means generous whitespace, cards over dense tables, an 8/16/24/32/48px scale. `balanced` (the default, and healthcare/legal/commerce) sits between the two. Read the density value out of `DESIGN_SYSTEM.md` and apply its spacing scale consistently — do not mix a compact table density with spacious card padding in the same build.

MOTION PROFILE: `subtle` means motion is reserved for essential state-change feedback only (save confirmations, validation errors, loading states) — durations under 200ms, never decorative. `moderate` (commerce, education) means motion reinforces state changes and guides attention (hover states, add-to-cart feedback, progress) at 150-300ms. `expressive` (creative only) means motion is itself a brand signal — page transitions and scroll-triggered reveals are expected, 300-500ms with expressive easing. Match the build's actual motion profile; do not add expressive animation to a `subtle`-profile build (it reads as off-brand) or leave a `expressive`-profile build motion-flat (it reads as unfinished).

DARK MODE: Every color role MUST also work under Tailwind's `dark:` prefix (see the `ui-components` and `frontend-design` skills for the broader dark-mode contract) — the `background`/`foreground` pair in particular needs a dark-mode counterpart before shipping any page, even though `DESIGN_SYSTEM.md`'s baseline only lists the light-mode hex values.

WHEN THIS FILE IS STALE: If `governance/DESIGN_SYSTEM.md`'s header says it was written by UX Intelligence (Phase 0) rather than UI/UX Pro Max (Phase 1B), and the build has since generated a PRD, treat the palette as a reasonable starting point but defer to any more specific art direction the PRD itself states explicitly (a stated brand color, an existing logo, a named competitor to differentiate from) — the vertical-keyword classifier cannot see those, only the generic industry pattern.
