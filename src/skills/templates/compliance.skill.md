REGIME AWARENESS: Before writing any code that touches user data, payments, or health/financial records, check `governance/COMPLIANCE_REQUIREMENTS.md` (generated by Phase 0's Compliance Detector) for which regimes apply to this build. A regime being absent from that file is not a guarantee — when in doubt, apply the strictest applicable pattern below.

HIPAA (health/medical/patient data): Encrypt PHI at rest (AES-256) and in transit (TLS 1.2+). Never log PHI to plaintext application logs or send it to a third-party analytics/error-tracking service without a signed BAA. Maintain an immutable audit log of every access to PHI. Enforce role-based access scoped to minimum-necessary.

GDPR (EU personal data): Obtain explicit opt-in consent before collecting or processing personal data — never pre-checked boxes. Provide self-service data export and deletion paths (Articles 15/17/20). Set no non-essential cookies before consent. Never retain personal data with no defined deletion policy.

PCI-DSS (payment/card data): Never store raw card numbers, CVV, or magnetic-stripe data — use a tokenized processor flow (Stripe Elements/Checkout) exclusively. Never log a card number even partially. Encrypt any stored payment metadata (tokens, last-4) at rest. TLS 1.2+ on every checkout/billing route.

SOX (public-company financial reporting): Maintain an immutable, tamper-evident audit trail on financial records — never hard-delete, use soft-delete/versioning. Enforce segregation of duties: no single role both creates and approves a transaction. Retain financial records 7+ years.

AUDIT LOGGING: When `auditLogRequired` is true for the applicable regime(s), every create/read/update/delete on regulated data must write an audit_log row: actor, action, resource, timestamp, before/after state where applicable. Audit log writes are never optional and never best-effort — a failed audit write should fail the operation it was logging, not silently drop it.

ENCRYPTION AT REST: When `encryptionAtRestRequired` is true, regulated columns/tables must use database-level or application-level encryption (Supabase pgcrypto, or field-level encryption before write) — plaintext storage of regulated data is a compliance failure, not a style preference.

DATA RETENTION: Respect the minimum retention floor from `COMPLIANCE_REQUIREMENTS.md` for HIPAA/SOX-governed data, and the data-minimization ceiling for GDPR-governed data — these can conflict for the same record (e.g. a EU patient's health data); when they do, flag the conflict rather than guessing which wins.
