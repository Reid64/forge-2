id: ux-copywriting
name: UX Copywriting Standards
domain: ui
tags: [ux, content]
applicablePromptTypes: [component, page, feature]
---

ERROR MESSAGES: State what happened and what the user should do about it — never a bare error code or generic "Something went wrong." E.g. "We couldn't save your changes because the connection dropped. Try again." not "Error: request failed."

BUTTON LABELS ARE VERBS: Button text names the action it performs — Save, Create, Delete, Send Invite — never a vague "OK", "Submit", or "Yes" when a more specific verb is available.

EMPTY STATES: Every empty state has four parts — an icon or illustration, a heading, a one-line description, and a clear call-to-action button. Never leave a list/table blank with no explanation of why it's empty or what to do next.

LOADING STATES ARE SPECIFIC: Loading copy names what's happening — "Saving your changes…", "Loading your dashboard…" — never a bare "Loading…" with no context when the surrounding UI can name the operation.

SUCCESS MESSAGES CONFIRM THE SPECIFIC ACTION: "Invoice #1042 sent to jane@example.com" not "Success!" — confirm what happened, to what, so the user doesn't have to guess whether it worked as intended.

TONE CONSISTENCY: Copy speaks in second person ("you"/"your"), avoids jargon the target user wouldn't know, and never blames the user for an error the system caused.
