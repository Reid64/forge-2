1. **P0** | No central env variable validation (env.ts missing) | src/lib/env.ts does not exist  
   **Details:** All 8 files access env vars via raw `process.env.VARIABLE_NAME` without type safety or runtime validation. No zod schema, no startup-time missing-var check. If required var is missing, app will fail at runtime (not build time).  
   **Files using process.env:** marketing/demo-request/route.ts, admin/google-calendar-auth (2), webhooks/stripe/route.ts, lib/stripe/client.ts, lib/supabase (3 files)  
   **Recommended fix:** Create src/lib/env.ts with zod schema validating all required vars at module load time. Example pattern:
   ```ts
   import { z } from 'zod'
   const envSchema = z.object({
     NEXT_PUBLIC_SUPABASE_URL: z.string().url(),
     NEXT_PUBLIC_SUPABASE_ANON_KEY: z.string().min(1),
     SUPABASE_SERVICE_ROLE_KEY: z.string().min(1),
     STRIPE_SECRET_KEY: z.string().startsWith('sk_'),
     // ... all required vars
   })
   export const env = envSchema.parse(process.env)
   ```
   Then replace all `process.env.X` with `env.X` for type safety + early failure.

2. **P1** | .env.example has 40+ variables but no programmatic check they're all set | .env.example vs .env.local  
   **Details:** .env.example is template, .env.local is active. No script verifies .env.local has all required keys from .env.example (non-OPTIONAL vars).  
   **Recommended fix:** Add verify-env script that parses .env.example, extracts non-# OPTIONAL vars, checks .env.local has them all. Run in pre-commit hook.
